# 算法与现场编码高频题

> 定位：Abound 已明确预告后续有 LeetCode 类编码题，但现有记录没有具体题目和现场表现。本文按 AI 应用岗与 Java/后端岗位的共同高频范围准备，不把练习题包装成真实面试经历。
>
> 现场表达统一按四步走：先说核心思路，再给不变量或关键步骤，然后报时间/空间复杂度，最后主动测易错边界。伪代码只保留能说明不变量的骨架，不堆完整题解。

## 1. 复杂度与现场表达

### Q001：拿到一段双重循环，怎么判断时间复杂度？

> **核心思路：** 我不会看到两层循环就直接说 O(n²)，要先看内外层执行次数是否相互独立。比如内层指针全程只向前走一次，整体可能仍是 O(n)。
>
> **不变量/关键步骤：** 先定义输入规模，再统计每个元素最多被访问几次；嵌套独立循环相乘，先后执行的阶段相加后取最高阶。
>
> **复杂度：** 给出最坏复杂度为主，必要时补平均和摊还复杂度；常数与低阶项在渐进表达中省略。
>
> **易错点：** 忽略排序、哈希退化、字符串切片等库调用成本；把 while 的语法层数当成实际访问次数。

### Q002：什么是摊还复杂度？动态数组扩容为什么仍能说追加 O(1)？

> **核心思路：** 单次扩容需要复制 O(n)，但扩容不是每次追加都发生，把多次操作总成本均摊后，尾部追加是摊还 O(1)。
>
> **不变量/关键步骤：** 容量按倍数增长时，一个元素被搬迁的次数受对数级约束；可以用聚合分析或势能法解释总复制量是 O(n)。
>
> **复杂度：** n 次追加总时间 O(n)，单次摊还 O(1)；某一次最坏仍是 O(n)，空间 O(n)。
>
> **易错点：** 把摊还 O(1) 说成任何单次都 O(1)；容量只加固定常数时，总复制可能退化到 O(n²)。

### Q003：递归算法的时间和空间复杂度怎么分析？

> **核心思路：** 时间看递归树有多少节点、每个节点做多少工作；空间看最大递归深度和每层额外状态，不是把所有调用节点简单相加。
>
> **不变量/关键步骤：** 先写递推式，例如二分是 T(n)=T(n/2)+O(1)，归并是 2T(n/2)+O(n)；再看是否有重叠子问题。
>
> **复杂度：** 二分递归时间 O(log n)、栈 O(log n)；朴素斐波那契时间 O(2^n)、栈 O(n)。
>
> **易错点：** 忘记递归栈算额外空间；Python/Java 没有可靠的通用尾递归优化，深递归可能栈溢出。

### Q004：“原地算法”就一定是 O(1) 空间吗？

> **核心思路：** 通常原地表示不再申请与输入规模同阶的辅助结构，但递归栈、返回结果和库函数临时空间仍要单独计算。
>
> **不变量/关键步骤：** 明确空间口径：是否包含输出、调用栈和输入本身；面试中我会先声明采用“额外空间”口径。
>
> **复杂度：** 双指针交换通常额外 O(1)；递归原地快排平均栈 O(log n)，最坏 O(n)。
>
> **易错点：** 函数参数切片会复制数组；递归虽然没显式数组也不等于 O(1)；返回新字符串通常需要 O(n) 输出空间。

### Q005：现场编码前应该先问哪些边界？

> **核心思路：** 我会先复述输入、输出、数据规模、是否有序、是否允许修改输入、重复值和空值语义，再决定算法，避免写完才发现题意不同。
>
> **不变量/关键步骤：** 先给朴素解和复杂度，再选择优化；写之前说清循环/递归不变量，写完用空、单元素、重复、极值和非法输入 dry run。
>
> **复杂度：** 这题没有固定算法复杂度，但我会在方案确认时明确目标复杂度和空间预算。
>
> **易错点：** 沉默写代码、过早猜隐藏条件、只测示例、标准库 API 不确定时硬编函数名。

## 2. 数组与哈希

### Q006：Two Sum 怎么做到 O(n)？

> **核心思路：** 一次遍历，用哈希表保存“已经看过的值到下标”，当前值 x 只要查询 target-x 是否存在。
>
> **不变量/关键步骤：** 处理当前位置前，表中只包含更早的元素；先查补数再写当前值，可以避免同一个元素被用两次。
>
> **复杂度：** 平均时间 O(n)，额外空间 O(n)；哈希极端退化需看实现，但面试通常按平均 O(1) 查询。
>
> **易错点：** 重复值如 `[3,3]`；先插入再查询导致 target=2x 时命中自己；题目要下标还是数值组合。

### Q007：Group Anagrams 的 key 怎么设计？

> **核心思路：** 把字母异位词映射到同一规范 key。通用做法是排序字符串；字符集固定时可以用频次数组转成不可变 key。
>
> **不变量/关键步骤：** 两个词是异位词，当且仅当规范 key 相同；哈希表 value 收集原字符串，不能只保存最后一个。
>
> **复杂度：** 排序法 O(n·k log k)，计数法 O(n·k)，空间 O(n·k)，n 为单词数、k 为平均长度。
>
> **易错点：** 频次数组直接作为可变 key；字符集并非只有小写字母；输出组内和组间顺序是否有要求。

### Q008：Longest Consecutive Sequence 为什么不用排序也能 O(n)？

> **核心思路：** 先把所有数字放进 Set，只从“前驱不存在”的数开始向后扩展，这样每条连续序列只扫描一次。
>
> **不变量/关键步骤：** x-1 不在 Set 时，x 才是序列起点；序列中的每个数只会在所属起点扩展时访问。
>
> **复杂度：** 平均时间 O(n)，空间 O(n)。排序法是 O(n log n) 且要处理重复。
>
> **易错点：** 从每个元素都向后扩展会退化 O(n²)；重复数字；整数边界做 x-1/x+1 时的溢出语言差异。

### Q009：和为 k 的连续子数组数量怎么求？

> **核心思路：** 用前缀和加频次哈希。当前位置前缀和为 s，之前出现过 s-k，就能组成和为 k 的子数组。
>
> **不变量/关键步骤：** 哈希表始终记录当前下标之前各前缀和出现次数；初始化 `freq[0]=1`，先累加答案再记录当前 s。
>
> **复杂度：** 时间 O(n)，空间 O(n)。
>
> **易错点：** 只保存下标而不是频次会漏掉多种起点；忘记空前缀；存在负数时不能用普通“和过大就左移”的滑窗。

### Q010：前缀和和差分数组分别解决什么？

> **核心思路：** 前缀和把静态区间求和变成两次查表；差分把多次区间增量更新变成端点修改，最后一次前缀恢复结果。
>
> **不变量/关键步骤：** 半开区间 `[l,r)` 的和是 pre[r]-pre[l]；闭区间增量可做 diff[l]+=v、diff[r+1]-=v。
>
> **复杂度：** 预处理 O(n)，单次区间和 O(1)；m 次差分更新 O(m)，最终恢复 O(n)，空间 O(n)。
>
> **易错点：** 闭区间/半开区间混用；r+1 越界；动态单点更新很多时前缀和不合适，应考虑树状数组或线段树。

### Q011：Product of Array Except Self 怎么不用除法？

> **核心思路：** 结果先存每个位置左边乘积，再从右往左维护右边乘积并相乘，不需要除法，也自然处理零。
>
> **不变量/关键步骤：** 第一遍结束后 ans[i] 等于 `nums[0..i)` 的乘积；第二遍变量 right 等于 `nums(i..n)` 的乘积。
>
> **复杂度：** 时间 O(n)，除输出外额外空间 O(1)。
>
> **易错点：** 空数组和单元素的定义；整数溢出；把输出数组计入辅助空间前要说明口径。

### Q012：Merge Intervals 的排序后扫描不变量是什么？

> **核心思路：** 按起点排序，结果列表最后一个区间代表目前合并后的最右范围；新区间重叠就扩右端，不重叠就新开一段。
>
> **不变量/关键步骤：** 扫描到第 i 个区间前，结果已经覆盖并正确合并所有之前区间，且互不重叠、按起点有序。
>
> **复杂度：** 排序 O(n log n)，扫描 O(n)，结果空间 O(n)。
>
> **易错点：** `[1,4]` 和 `[4,5]` 是否算重叠取决于题意；空输入；原地修改输入区间可能影响调用方。

### Q013：Sort Colors 怎么一趟完成？

> **核心思路：** 用荷兰国旗三指针：left 左侧全是 0，right 右侧全是 2，cur 扫描未知区间。
>
> **不变量/关键步骤：** `[0,left)` 为 0，`[left,cur)` 为 1，`(right,n)` 为 2，`[cur,right]` 未分类；cur 遇 2 交换后不能立刻前进。
>
> **复杂度：** 时间 O(n)，额外空间 O(1)。
>
> **易错点：** 与 right 交换来的值尚未检查却 cur++；循环条件写成 cur<right 漏最后一个；输入包含非法值怎么办。

### Q014：原地旋转 n×n 矩阵 90 度怎么做？

> **核心思路：** 顺时针旋转可以先沿主对角线转置，再把每一行反转；也可以四元组分层交换，但前者更易讲清。
>
> **不变量/关键步骤：** 转置后元素 `(i,j)` 到 `(j,i)`，行反转后到 `(j,n-1-i)`，正好是顺时针映射。
>
> **复杂度：** 时间 O(n²)，额外空间 O(1)。
>
> **易错点：** 非方阵不能直接原地这样做；转置循环重复交换；顺时针和逆时针的反转方向弄反。

## 3. 双指针与滑动窗口

### Q015：3Sum 怎么去重？

> **核心思路：** 先排序，枚举第一个数，再用左右指针找另外两个。固定值过大可提前结束，和过小左移、过大右移。
>
> **不变量/关键步骤：** 固定 i 后，左右指针之间是尚未检查区域；i 与上一个值相同就跳过，找到解后左右两侧都跳过重复值。
>
> **复杂度：** 排序 O(n log n)，双指针总 O(n²)，额外空间取决于排序实现，结果空间不计。
>
> **易错点：** 只去重 i 不去重左右；使用同一元素；整数和溢出；误用 Set 事后去重掩盖重复逻辑。

### Q016：Container With Most Water 为什么移动短板？

> **核心思路：** 面积由宽度乘两端较短高度决定。宽度缩小时，移动长板不可能让当前短板提高，所以只移动短板才可能找到更大面积。
>
> **不变量/关键步骤：** 当前两端面积计算后，较短端与任何更靠内的另一端组合都不会因为保留它而超过当前宽度上界，因此可以排除。
>
> **复杂度：** 时间 O(n)，空间 O(1)。
>
> **易错点：** 移动长板；相等高度时任意移动一边都可以但要保持推进；高度或乘积类型溢出。

### Q017：Move Zeroes 怎么保持非零元素相对顺序？

> **核心思路：** slow 指向下一个非零写入位置，fast 扫描数组；遇到非零就写到 slow 并推进，最后把剩余位置补零。
>
> **不变量/关键步骤：** `[0,slow)` 始终是已经扫描元素中的全部非零值，且相对顺序不变。
>
> **复杂度：** 时间 O(n)，空间 O(1)。交换版也 O(n)，但要避免无意义自交换。
>
> **易错点：** 覆盖后没有补零；误把题目写成排序；需要原地时创建新数组。

### Q018：Longest Substring Without Repeating Characters 的窗口不变量是什么？

> **核心思路：** 维护一个没有重复字符的窗口，右指针加入字符；如果重复，就把左边界跳到该字符上次位置之后。
>
> **不变量/关键步骤：** 窗口 `[left,right]` 内字符唯一；用 lastIndex 时新 left 取 `max(left,last[c]+1)`，不能向后退。
>
> **复杂度：** 时间 O(n)，空间 O(字符集大小)。每个位置最多被左右指针处理常数次。
>
> **易错点：** Java 按 char 处理 Unicode code point 的差异；left 回退；更新答案和 lastIndex 的顺序。

### Q019：Minimum Window Substring 怎么判断窗口已经满足？

> **核心思路：** 记录目标字符需求和窗口计数，用 formed 表示已有多少种字符达到所需数量；满足后不断收缩左边找最短。
>
> **不变量/关键步骤：** `formed == requiredKinds` 时窗口覆盖目标；移出字符导致其数量从满足变不足时 formed--。
>
> **复杂度：** 时间 O(|s|+|t|)，空间 O(字符集大小)。
>
> **易错点：** formed 统计字符种类，不是总字符数；目标有重复字符；答案长度和左右边界更新的 off-by-one。

### Q020：Permutation in String 怎么用固定长度窗口？

> **核心思路：** 异位词窗口长度固定为模式串长度，维护字符频次或差异计数，右边加入一个、超长时左边移出一个。
>
> **不变量/关键步骤：** 每次判断时窗口长度恰好等于模式长度；差异为零意味着频次完全相同。
>
> **复杂度：** 时间 O(n+字符集)，空间 O(字符集)。固定小写字母时可视为 O(1) 空间。
>
> **易错点：** 每个窗口重新排序变成 O(n·k log k)；窗口缩小条件；空模式串的约定。

### Q021：Sliding Window Maximum 为什么用单调队列？

> **核心思路：** 双端队列保存下标，并让对应值单调递减；队首就是当前窗口最大值，新值进入时把队尾更小值弹掉。
>
> **不变量/关键步骤：** 队列下标都在当前窗口内且值递减；每轮先清理过期队首，再维护单调性并加入当前下标。
>
> **复杂度：** 时间 O(n)，空间 O(k)，每个下标最多进出队列一次。
>
> **易错点：** 队列存值后无法判断是否过期；重复值处理；窗口形成前就写结果；k 非法或大于 n。

### Q022：Trapping Rain Water 的双指针依据是什么？

> **核心思路：** 维护左右最大高度。较小一侧的最大值决定该侧当前位置能接多少水，因此先处理较小侧并向内移动。
>
> **不变量/关键步骤：** leftMax 是左侧已见最大，rightMax 是右侧已见最大；当 leftMax<=rightMax 时，left 的水量已可确定。
>
> **复杂度：** 时间 O(n)，空间 O(1)。前后缀数组法时间 O(n)、空间 O(n)。
>
> **易错点：** 先移动指针还是先计算导致漏算；负高度是否允许；与“最大容器”题的面积逻辑混淆。

## 4. 链表

### Q023：反转单链表的循环不变量是什么？

> **核心思路：** 用 prev、cur、next 三个指针逐个改向；每次先保存 next，再让 cur.next 指向 prev。
>
> **不变量/关键步骤：** 循环开始时 prev 是已反转部分的头，cur 是未处理部分的头，两部分合起来仍覆盖原链表全部节点。
>
> **复杂度：** 时间 O(n)，空间 O(1)；递归版时间 O(n)、栈 O(n)。
>
> **易错点：** 没先保存 next 就断链；最后返回 cur 而不是 prev；空链表和单节点。

### Q024：判断链表有环为什么用快慢指针？

> **核心思路：** slow 每次一步，fast 每次两步；有环时两者在环内一定相遇，无环时 fast 先到 null。
>
> **不变量/关键步骤：** 进入环后，fast 相对 slow 每轮追近一步；有限环长下必然同位置。
>
> **复杂度：** 时间 O(n)，空间 O(1)。用 Set 也能 O(n) 时间但空间 O(n)。
>
> **易错点：** fast 和 fast.next 的空判断；初始化相同后在循环前直接判断会误报；只会背结论不会解释相对速度。

### Q025：怎么找到链表环的入口？

> **核心思路：** 快慢指针相遇后，一个指针回到头，两个都每次走一步，再次相遇的位置就是环入口。
>
> **不变量/关键步骤：** 设头到入口为 a、入口到首次相遇为 b、环余长 c，由快指针路程是慢指针两倍可推出 a 与从相遇点到入口同余。
>
> **复杂度：** 时间 O(n)，空间 O(1)。
>
> **易错点：** 首次相遇后仍让 fast 每次走两步；无环时继续第二阶段；代数解释把环长倍数漏掉。

### Q026：合并两个有序链表为什么建议用 dummy 节点？

> **核心思路：** dummy 统一处理结果头节点，tail 每次接较小节点并前进，最后接上未耗尽的一条链。
>
> **不变量/关键步骤：** tail 前面的结果始终有序，且包含两条输入中所有已消费节点；未消费部分仍各自有序。
>
> **复杂度：** 时间 O(m+n)，空间 O(1)，复用原节点；递归版额外栈 O(m+n)。
>
> **易错点：** 忘记接剩余链；tail 前进顺序错误形成环；题目是否允许修改原链表。

### Q027：删除链表倒数第 n 个节点怎么一趟完成？

> **核心思路：** 用 dummy，fast 先走 n 步，再让 fast、slow 同步走到 fast.next 为 null，此时 slow.next 是待删节点。
>
> **不变量/关键步骤：** 同步阶段 fast 与 slow 始终相差 n 个节点；dummy 让删除头节点无需特判。
>
> **复杂度：** 时间 O(L)，空间 O(1)。
>
> **易错点：** 相差 n 还是 n+1 的定义不一致；n 越界；循环停在 fast 还是 fast.next；忘记断开被删节点在某些语言中的引用。

### Q028：两个无环链表的交点怎么找？

> **核心思路：** 两个指针分别走 A 后走 B、走 B 后走 A，路径总长度相同；有交点会在交点相遇，无交点最终都为 null。
>
> **不变量/关键步骤：** 每个指针最多走 m+n 步，切换头节点抵消两链表长度差；比较的是节点身份，不是节点值。
>
> **复杂度：** 时间 O(m+n)，空间 O(1)。
>
> **易错点：** 用 value 相等判断；输入链表有环时该算法前提不成立；切换条件写错造成无限循环。

### Q029：判断回文链表怎么做到 O(1) 额外空间？

> **核心思路：** 快慢指针找中点，反转后半段，再从两端比较；如果接口要求不改变输入，比较后恢复后半段。
>
> **不变量/关键步骤：** slow 定位后半段起点要根据奇偶长度统一；比较阶段两指针对应回文位置。
>
> **复杂度：** 时间 O(n)，空间 O(1)。
>
> **易错点：** 奇数长度中间节点处理；反转断链；忘记恢复导致调用方观察到链表被修改。

### Q030：复制带随机指针的链表有哪些做法？

> **核心思路：** 稳妥做法是哈希表保存原节点到新节点映射；进阶可把复制节点插在原节点后面，利用相邻关系设置 random，再拆链。
>
> **不变量/关键步骤：** 映射法两遍：先建全部节点，再连 next/random；穿插法保证原节点后的节点就是其副本。
>
> **复杂度：** 两种时间都是 O(n)；映射空间 O(n)，穿插法额外 O(1)。
>
> **易错点：** random 为 null；拆链时破坏原链；题目对“额外空间”是否把新链表本身排除。

## 5. 栈与队列

### Q031：Valid Parentheses 怎么保证括号匹配？

> **核心思路：** 遇到左括号入栈，遇到右括号时必须与栈顶匹配并弹出，最终栈为空才有效。
>
> **不变量/关键步骤：** 栈中保存所有尚未匹配的左括号，顺序就是它们必须被关闭的逆序。
>
> **复杂度：** 时间 O(n)，空间 O(n)。
>
> **易错点：** 右括号出现时栈为空；只检查局部不检查最终栈空；输入含非括号字符的处理约定。

### Q032：Min Stack 怎么让 `getMin()` O(1)？

> **核心思路：** 数据栈之外维护最小值栈，或每个节点同时保存当前最小值；入栈时更新，出栈时同步。
>
> **不变量/关键步骤：** min 栈栈顶始终是当前数据栈全部元素的最小值；遇到等于最小值的重复元素也必须记录。
>
> **复杂度：** push/pop/top/getMin 都 O(1)，空间 O(n)。
>
> **易错点：** 只在严格更小时压 min，重复最小值弹出后丢失；空栈调用语义；用一个差值编码时整数溢出。

### Q033：Daily Temperatures 为什么用单调栈？

> **核心思路：** 栈保存尚未找到更高温度的下标，并保持对应温度单调递减；当前更高时连续弹栈并计算距离。
>
> **不变量/关键步骤：** 栈内下标递增、温度单调不升；被弹出的下标第一次遇到的更高温就是最近答案。
>
> **复杂度：** 时间 O(n)，空间 O(n)，每个下标最多入栈和出栈一次。
>
> **易错点：** 栈存温度而非下标导致无法算距离；相等温度是否弹出；没有更高温保持 0。

### Q034：Largest Rectangle in Histogram 的哨兵有什么作用？

> **核心思路：** 用单调递增栈。遇到更矮柱子时，弹出高柱，以当前下标作为右边界、弹栈后栈顶作为左边界计算面积；末尾加 0 强制清空。
>
> **不变量/关键步骤：** 栈保存高度递增的下标；弹出 mid 后宽度是 `right-left-1`。
>
> **复杂度：** 时间 O(n)，空间 O(n)。
>
> **易错点：** 宽度少减或多减 1；相等高度的保留策略不一致；没有前后哨兵导致大量边界分支。

### Q035：用两个栈实现队列，什么时候搬运元素？

> **核心思路：** input 负责入队，output 负责出队；只有 output 为空时才把 input 全部倒过去，保证摊还效率。
>
> **不变量/关键步骤：** output 栈顶始终是当前队首；一次倒栈后不要因为新入队又重复搬运。
>
> **复杂度：** 每个元素最多进出两个栈，push 摊还 O(1)，pop/peek 摊还 O(1)，空间 O(n)。
>
> **易错点：** 每次 pop 都全量倒来倒去变 O(n)；空队列；把最坏单次 O(n) 误说成任何一次都 O(1)。

### Q036：用一个队列实现栈怎么做？

> **核心思路：** 每次 push 新元素后，把之前元素依次轮转到队尾，使新元素成为队首；这样 pop 直接出队。
>
> **不变量/关键步骤：** 每次 push 完，队列顺序从队首到队尾就是栈顶到栈底。
>
> **复杂度：** push O(n)，pop/top O(1)，空间 O(n)；也可把成本放到 pop。
>
> **易错点：** 轮转次数应是加入前的队列长度；空结构；混淆“一个队列”与底层允许的操作集合。

### Q037：带括号的加减乘除表达式怎么现场实现？

> **核心思路：** 先确认语法范围。常见方案是双栈或递归下降：数字解析、运算符优先级、括号递归分别处理。
>
> **不变量/关键步骤：** 双栈中运算符栈保持待计算操作；新操作符到来时先计算优先级不低于它的旧操作。递归下降则让每层函数对应一种优先级。
>
> **复杂度：** 时间 O(n)，空间 O(n)。
>
> **易错点：** 一元负号、空格、多位数、整数除法规则和除零；题目若不含乘除或括号，不要过度实现完整解析器。

## 6. 二叉树

### Q038：前序、中序、后序遍历的递归定义分别是什么？

> **核心思路：** 前序是根左右，中序是左根右，后序是左右根；递归只要把“处理根”的位置放对。
>
> **不变量/关键步骤：** 每次调用完整处理以当前节点为根的子树；空节点立即返回。
>
> **复杂度：** 时间 O(n)，递归栈平均 O(h)、最坏 O(n)，输出 O(n)。
>
> **易错点：** 把二叉搜索树的中序有序性质推广到普通树；忘记递归栈空间；现场要求迭代却只会递归。

### Q039：二叉树层序遍历怎么区分每一层？

> **核心思路：** BFS 队列中每轮先读取当前队列长度 size，正好代表本层节点数；处理 size 个节点并把孩子入队。
>
> **不变量/关键步骤：** 每轮开始时队列只包含当前层全部节点；本轮新加入的节点属于下一层，不在本轮继续处理。
>
> **复杂度：** 时间 O(n)，空间 O(w)，w 是最大层宽。
>
> **易错点：** 在循环中使用不断变化的 queue.size() 作为本层上限；把 null 节点入队；空树返回格式。

### Q040：求二叉树最大深度，递归和 BFS 怎么选？

> **核心思路：** 递归是 `1+max(left,right)`，最直接；极深偏斜树担心栈溢出时可用 BFS/DFS 显式栈。
>
> **不变量/关键步骤：** 递归返回值定义为“当前节点到叶子的最大节点数”，空节点深度为 0。
>
> **复杂度：** 时间 O(n)；递归空间 O(h)，BFS 空间 O(w)。
>
> **易错点：** 深度按节点数还是边数；只遍历一侧；把平衡树空间固定说成 O(log n) 而忽略最坏偏斜。

### Q041：Invert Binary Tree 的本质是什么？

> **核心思路：** 对每个节点交换左右孩子，再递归或迭代处理子树；先交换还是后交换都可以，只要遍历不丢节点。
>
> **不变量/关键步骤：** 处理完成后，以当前节点为根的子树已经是原子树的镜像。
>
> **复杂度：** 时间 O(n)，空间 O(h) 递归栈或 O(w) 队列。
>
> **易错点：** 原地修改还是返回新树要先确认；交换后又按旧引用递归；共享节点结构不是普通树时可能重复处理。

### Q042：Symmetric Tree 怎么比较两棵镜像子树？

> **核心思路：** 成对比较 left.left 与 right.right、left.right 与 right.left；两个都空为真，一个空或值不同为假。
>
> **不变量/关键步骤：** 函数 `mirror(a,b)` 的语义始终是判断两棵子树是否互为镜像，而不是普通相等。
>
> **复杂度：** 时间 O(n)，空间 O(h)。
>
> **易错点：** 比成 a.left 对 b.left；空节点判断顺序；只比较一层值没有继续递归结构。

### Q043：Validate Binary Search Tree 为什么不能只比较父子？

> **核心思路：** BST 要满足整个左子树都小于当前节点、整个右子树都大于当前节点。可递归传上下界，或检查中序严格递增。
>
> **不变量/关键步骤：** 每个节点必须落在祖先约束形成的开区间 `(low,high)`；进入左子树更新 high，右子树更新 low。
>
> **复杂度：** 时间 O(n)，空间 O(h)。
>
> **易错点：** 只比直接孩子；边界用 int 最小最大导致溢出；重复值是否允许要按题意；中序 previous 的初始化。

### Q044：BST 第 k 小元素怎么求？

> **核心思路：** BST 中序遍历是升序，遍历到第 k 个节点即答案；迭代栈可以提前停止。
>
> **不变量/关键步骤：** 栈保存从当前节点向左路径，弹出的节点按升序出现；每弹一个 k--。
>
> **复杂度：** 时间 O(h+k)，空间 O(h)；完整遍历是 O(n)。
>
> **易错点：** k 是 1-based；k 越界；树频繁查询时每次遍历，可能应在节点维护子树大小。

### Q045：二叉树最近公共祖先的递归含义是什么？

> **核心思路：** 普通二叉树中，当前节点为 null、p 或 q 就返回；左右递归都非空说明 p、q 分居两侧，当前节点是 LCA，否则返回非空侧。
>
> **不变量/关键步骤：** 递归返回值表示“当前子树里找到的 p/q 或它们的公共祖先”。
>
> **复杂度：** 时间 O(n)，空间 O(h)。
>
> **易错点：** 题目是否保证 p、q 都存在；节点值重复时要比较身份；BST 可利用大小关系做到 O(h)，不要混题。

### Q046：Path Sum 这类题怎么区分“存在”“列出路径”和“任意路径”？

> **核心思路：** 根到叶存在路径用递归减 target；列出全部路径需要 path 选择与撤销；任意起止路径通常要后序统计向下贡献或前缀和。
>
> **不变量/关键步骤：** 先明确路径必须从根开始、到叶结束还是任意节点；不同定义对应不同状态，不能套同一模板。
>
> **复杂度：** 单纯存在判断 O(n)、栈 O(h)；复制所有输出路径还要计入结果总长度。
>
> **易错点：** 到 null 才判断而不是叶子；负数下错误剪枝；path 回溯忘记 remove；把“节点数”与“路径和”混淆。

### Q047：二叉树直径为什么要后序遍历？

> **核心思路：** 每个节点需要先知道左右子树最大向下深度，经过该节点的直径是 leftDepth+rightDepth，同时向父返回 `1+max`。
>
> **不变量/关键步骤：** 递归返回的是单边最大深度，全局答案记录任意节点处的双边最大值，两个含义不能混。
>
> **复杂度：** 时间 O(n)，空间 O(h)。
>
> **易错点：** 直径按边数还是节点数；只返回左右深度之和导致父节点无法继续；全局变量跨测试未重置。

### Q048：根据前序和中序构造二叉树怎么优化到 O(n)？

> **核心思路：** 前序首元素是根，在中序中定位根后确定左右子树大小；用哈希表保存中序值到下标，递归传区间而不是切片。
>
> **不变量/关键步骤：** 前序区间和中序区间始终描述同一组节点；左子树长度决定前序分界。
>
> **复杂度：** 时间 O(n)，哈希和递归空间 O(n)。切片和线性查找可能退化到 O(n²)。
>
> **易错点：** 值不唯一时映射不成立；区间闭开定义混乱；左右子树长度 off-by-one；输入遍历不合法。

### Q049：二叉树序列化为什么要保留 null？

> **核心思路：** 只记录节点值无法唯一恢复结构；前序加 null 标记，或层序加必要空位，都能让反序列化知道孩子缺失位置。
>
> **不变量/关键步骤：** 序列化和反序列化必须使用完全对称的 token 协议；前序反序列化每消费一个 token 就构造一个节点或空子树。
>
> **复杂度：** 时间 O(n)，输出和辅助空间 O(n)。
>
> **易错点：** 分隔符与转义；负数和空树；层序尾部 null 是否裁剪要与协议一致；不可信输入的深度和大小限制。

## 7. 堆与 Top K

### Q050：数组中第 k 大元素为什么用大小为 k 的小顶堆？

> **核心思路：** 小顶堆只保留目前最大的 k 个数，堆顶是这 k 个里的最小值，也就是扫描结束后的第 k 大。
>
> **不变量/关键步骤：** 处理任意前缀后，堆中是该前缀最大的至多 k 个元素；新值入堆后超过 k 就弹最小。
>
> **复杂度：** 时间 O(n log k)，空间 O(k)；快速选择平均 O(n)、最坏 O(n²)。
>
> **易错点：** 第 k 大不是第 k 个不同值；k 越界；误用大顶堆保留 k 个导致弹错方向。

### Q051：Top K 高频元素怎么做？

> **核心思路：** 我会先用哈希表统计频次，再维护一个大小为 k 的小顶堆，堆里按频次排序。这样扫描完后，堆中就是频次最高的 k 个元素；如果频次上界明确，也可以用桶排序做到线性时间。
>
> **不变量/关键步骤：** 处理完任意一批频次记录后，堆里始终保留当前频次最大的至多 k 个元素；新元素入堆后超过 k，就弹掉频次最小的那个。
>
> **复杂度：** 哈希统计 O(n)，堆处理 O(m log k)，其中 m 是不同元素数；空间 O(m+k)。桶排序时间和空间都是 O(n)。
>
> **易错点：** 把元素值当频次比较；相同频次下误以为顺序固定；k 大于不同元素数；最后从小顶堆弹出的结果是逆序，题目若要求顺序要再处理。

### Q052：合并 k 个升序链表为什么适合用堆？

> **核心思路：** 我会把每条非空链表的头节点放进小顶堆，每次取最小节点接到结果链表，再把它的 next 放回堆。堆里只保留每条链表当前尚未消费的最小候选。
>
> **不变量/关键步骤：** 堆顶始终是所有未合并节点中可以确定的最小值；一个节点出堆后，只需要补入它所在链表的下一个节点，不需要把整条链表都入堆。
>
> **复杂度：** 总节点数为 n，时间 O(n log k)，堆空间 O(k)；结果若复用原节点，额外链表空间 O(1)。
>
> **易错点：** 空链表入堆；比较器用减法造成整数溢出；Java 的节点值相同且比较器不稳定时错误比较对象；忘记推进对应链表或形成旧链表环。

### Q053：数据流中位数怎么设计？

> **核心思路：** 我会用两个堆：大顶堆保存较小的一半，小顶堆保存较大的一半。中位数只需要看两个堆顶，不需要每次把全部数据重新排序。
>
> **不变量/关键步骤：** 第一，大顶堆所有元素都不大于小顶堆元素；第二，两个堆大小差最多为 1。我通常让大顶堆多一个元素，插入后通过堆顶搬运恢复这两个不变量。
>
> **复杂度：** 每次插入 O(log n)，查询中位数 O(1)，空间 O(n)。
>
> **易错点：** 偶数个元素求平均时整数溢出或整除截断；只平衡数量却没保证左右有序；Java 大顶堆比较器写成 `b-a` 溢出；空数据流直接查询。

### Q054：持续到来的数据怎么维护实时 Top K？

> **核心思路：** 如果只要求当前最大的 k 个值，我会维护大小为 k 的小顶堆；如果要求 Top K 高频项，还要同时维护频次表，并处理元素频次变化后堆中旧优先级失效的问题。
>
> **不变量/关键步骤：** 数值 Top K 的不变量是堆中保留已处理前缀最大的 k 个值。高频 Top K 可以用“新版本入堆、弹出时校验当前频次”的惰性删除，或者用支持更新键值的有序结构。
>
> **复杂度：** 数值流每条 O(log k)、空间 O(k)；高频流通常每次 O(log m)，空间取决于不同元素数和惰性旧记录数。
>
> **易错点：** 把离线 Top K 方案直接套到频次不断变化的流；旧堆项未失效；没有定义滑动窗口还是全历史；并发更新丢计数；无限数据下频次表没有淘汰策略。

### Q055：任务调度器什么时候用优先队列，怎么避免饿死？

> **核心思路：** 我会把可执行任务按优先级、计划时间或截止时间放进优先队列，调度线程每次取当前最应该执行的任务。单靠静态优先级可能让低优先任务一直等，所以生产设计还要加入 aging 或等待时间权重。
>
> **不变量/关键步骤：** 队首始终是当前调度规则下优先级最高的可运行任务；尚未到执行时间的任务不能提前跑；任务取出和状态从 READY 改成 RUNNING 要形成一个原子领取动作。
>
> **复杂度：** 入队和出队 O(log n)，查看队首 O(1)，空间 O(n)。分布式场景的瓶颈通常在持久化、锁竞争和任务执行，不只是堆操作。
>
> **易错点：** 比较器与 equals 不一致；优先级相同没有稳定次序；失败任务立即重入造成热循环；低优先级饿死；多线程同时取到同一任务；系统时间回拨影响延时任务。

## 8. 二分查找

### Q056：二分查找最重要的不变量是什么？

> **核心思路：** 我不会死背某个模板，而是先决定搜索区间是闭区间 `[left,right]` 还是左闭右开 `[left,right)`，然后保证答案如果存在就一直留在这个区间里。
>
> **不变量/关键步骤：** 闭区间写法通常是 `left <= right`，排除 mid 后用 `mid-1` 或 `mid+1`；左闭右开写法通常是 `left < right`，右边界更新为 mid。整个过程不能混用两套边界语义。
>
> **复杂度：** 时间 O(log n)，空间 O(1)；递归写法会有 O(log n) 调用栈。
>
> **易错点：** `mid=(left+right)/2` 溢出；循环条件和边界更新不匹配导致漏解或死循环；输入没有单调性；找到一个值就返回但题目实际要边界。

### Q057：怎么找有序数组中目标值的第一个和最后一个位置？

> **核心思路：** 我会做两次边界二分：第一次找第一个大于等于 target 的位置，第二次找第一个大于 target 的位置，后者减一就是最后位置。
>
> **不变量/关键步骤：** lower bound 左边都小于 target，右边候选都大于等于 target；upper bound 左边都小于等于 target，右边候选都大于 target。最后还要检查下标是否越界且值真的等于 target。
>
> **复杂度：** 两次二分仍是 O(log n)，空间 O(1)。
>
> **易错点：** 把 `>=` 和 `>` 写反；目标不存在时直接返回插入点；最后位置用 `upperBound-1` 后变成 -1；空数组和全相等数组边界错误。

### Q058：旋转有序数组里怎么二分查找目标值？

> **核心思路：** 每轮至少有一半仍然有序。我先判断左半还是右半有序，再看 target 是否落在这段有序区间里，从而排除另一半。
>
> **不变量/关键步骤：** 答案始终留在 `[left,right]`；判断区间归属时，一边用包含、一边用排除，边界条件必须配套。没有重复元素时可以稳定判断哪半有序。
>
> **复杂度：** 无重复元素时 O(log n)，空间 O(1)；存在大量重复元素时，为消除歧义可能退化到 O(n)。
>
> **易错点：** 旋转点附近的等号处理；target 等于端点；有重复值时仍宣称严格 O(log n)；把“找目标”和“找最小值”的判断条件混在一起。

### Q059：旋转有序数组的最小值怎么找？

> **核心思路：** 我会把 mid 和 right 比较。若 `nums[mid] > nums[right]`，最小值一定在 mid 右侧；否则最小值在包含 mid 的左半边。
>
> **不变量/关键步骤：** 搜索区间始终包含最小值；右边界作为参照是因为右端所在的有序段能帮助判断 mid 位于旋转前段还是后段。收敛到 `left==right` 时就是答案。
>
> **复杂度：** 无重复时 O(log n)，空间 O(1)；有重复且 `nums[mid]==nums[right]` 时只能令 right--，最坏 O(n)。
>
> **易错点：** `nums[mid] <= nums[right]` 时写成 `right=mid-1` 导致跳过 mid；数组本身未旋转；单元素；重复值导致错误排除真正最小值。

### Q060：不用库函数怎么求整数平方根？

> **核心思路：** 我要找的是最大的整数 x，使 `x*x <= n`，这是典型的“最后一个满足条件的位置”，可以对答案范围做二分。
>
> **不变量/关键步骤：** 保存当前可行答案；mid 可行就记录并向右找更大值，不可行就向左缩。为了避免乘法溢出，我会比较 `mid <= n/mid`，并单独处理 n 为 0。
>
> **复杂度：** 时间 O(log n)，空间 O(1)。牛顿迭代也很快，但现场先把边界正确性讲清楚更重要。
>
> **易错点：** `mid*mid` 溢出；把向下取整写成寻找精确平方；n 为 0 或 1；使用浮点比较产生精度问题；负数输入没有按接口约定处理。

### Q061：什么叫“二分答案”？怎么判断能不能用？

> **核心思路：** 当答案本身有一个有序范围，而且“给定候选值 x 是否可行”具有单调性时，我会二分答案。常见例子是最小运载能力、最大最小距离和限定天数内的最小速度。
>
> **不变量/关键步骤：** 先证明可行集合形如 `[x, +∞)` 或不可行集合形如某个连续区间，再写 `check(x)`；边界要用题意能保证覆盖答案的最小值和最大值。
>
> **复杂度：** 总时间是 O(check 的成本 × log 答案范围)，额外空间取决于 check；不能只报 O(log n)。
>
> **易错点：** 没证明单调性就硬套；上下界过小漏答案或过大溢出；check 中也有整数溢出；求最小可行值和最大可行值使用了相反模板。

## 9. 回溯

### Q062：子集问题的回溯树怎么理解？

> **核心思路：** 我把每个元素看成选或不选，也可以用 start 下标枚举下一项。每到一个节点，当前 path 本身就是一个合法子集，所以先加入结果，再继续扩展。
>
> **不变量/关键步骤：** path 只包含下标小于当前递归边界且已经选择的元素；下一层只能从更大的下标选，避免同一组合因顺序不同被重复生成；递归返回前撤销最后一次选择。
>
> **复杂度：** 一共有 2^n 个子集，复制输出的时间和结果空间都是 O(n·2^n)，递归栈 O(n)。
>
> **易错点：** 把同一个可变 path 引用直接放进结果；忘记撤销；start 没有前进造成重复或死递归；输入含重复元素时未先排序并做同层去重。

### Q063：全排列为什么要用 used 数组？

> **核心思路：** 排列关心顺序，每一层都可以从所有尚未使用的元素中选一个。`used[i]` 表示当前路径里这个位置的元素已经被占用，回溯时恢复。
>
> **不变量/关键步骤：** path 中不会重复使用同一个输入下标；当 path 长度等于 n 时得到一个完整排列；每次递归都严格增加 path 长度，返回时同时撤销 path 和 used。
>
> **复杂度：** 输出规模是 n!，复制排列的时间 O(n·n!)，递归栈和 used 空间 O(n)。
>
> **易错点：** 用“值是否在 path 中”代替 used，遇到重复值出错且查询更慢；去重排列时同层规则写错；只撤销 path 没撤销 used；结果保存引用。

### Q064：组合总和怎么剪枝和处理重复？

> **核心思路：** 我会先确认候选数能否重复使用。允许重复时，递归下一层仍从当前下标开始；每个候选只能用一次时从 `i+1` 开始。排序后可以在剩余值不足时提前停止。
>
> **不变量/关键步骤：** path 的和加 remaining 始终等于 target；remaining 为 0 才收集结果；候选为正数时 remaining 小于 0 可剪枝；同一递归层跳过相同值避免重复组合。
>
> **复杂度：** 最坏是指数级，常写 O(b^d)，b 是分支数、d 约为 target/最小正数；空间包括递归栈和输出。
>
> **易错点：** 候选含 0 或负数时继续按正数剪枝导致无限递归；可重复与不可重复的 start 更新混淆；跨层错误去重；排序后忘记说明改变输入。

### Q065：生成合法括号为什么不需要最后再逐个校验？

> **核心思路：** 我在生成过程中就只走合法前缀：左括号数量不能超过 n，右括号数量不能超过左括号。这样到长度 2n 时自然就是合法答案。
>
> **不变量/关键步骤：** 任意前缀都满足 `right <= left <= n`；还能放左括号就尝试左，只有 `right < left` 才能放右；长度达到 2n 时收集。
>
> **复杂度：** 合法答案数是第 n 个 Catalan 数，生成时间可写 O(Cn·n)，递归和 path 空间 O(n)，另计输出。
>
> **易错点：** 只限制左右各 n 个却允许非法前缀；终止条件提前；StringBuilder 撤销下标错误；把所有 2^(2n) 字符串生成后再校验，浪费大量搜索。

### Q066：单词搜索为什么要原地标记再恢复？

> **核心思路：** 我会从每个可能的起点做 DFS，匹配当前字符后临时把格子标成已访问，向四个方向找下一个字符，返回前恢复。这样一条路径不会重复使用同一格。
>
> **不变量/关键步骤：** 进入 DFS 时当前位置与 word[index] 匹配；当前递归路径上的格子都处于已访问状态；无论成功还是失败，退出当前分支前都要按约定恢复现场。
>
> **复杂度：** 棋盘 m×n、单词长度 L，最坏时间 O(mn·4^L)，更精确可按首步后约 3 个方向估计；递归栈 O(L)。
>
> **易错点：** 越界检查顺序错误；成功提前返回导致原地标记没恢复并污染后续调用；允许对角线但题目只允许四方向；空单词和字符频次没有先做快速失败判断。

### Q067：回文分割怎么把判断回文和搜索组合起来？

> **核心思路：** 我从 start 枚举子串结束位置，只有当前子串是回文时才把它加入 path 并递归剩余部分。回文判断可以现场双指针，也可以先用 DP 预处理。
>
> **不变量/关键步骤：** path 中每一段都是回文，且这些段首尾相接恰好覆盖 `[0,start)`；start 到字符串末尾时，当前 path 才是一个完整分割。
>
> **复杂度：** 输出本身最坏指数级；预处理回文 O(n²) 时间和空间，回溯最坏约 O(n·2^n) 含结果复制。
>
> **易错点：** Java `substring` 的结束下标是开区间；空字符串语义；每次重新判断回文导致额外重复成本；只找一个分割却误写成列出全部，或反过来。

### Q068：N 皇后回溯时为什么只需要检查三组集合？

> **核心思路：** 我按行放皇后，每行只放一个，因此只要判断列、主对角线 `row-col` 和副对角线 `row+col` 是否冲突，不需要扫描整个棋盘。
>
> **不变量/关键步骤：** 进入第 row 行时，前 row 行各有且仅有一个皇后，并且三组占用集合都无冲突；选择一列后同时加入三组集合，递归返回时同时删除。
>
> **复杂度：** 粗略上界 O(n!)，集合和递归空间 O(n)，若保存棋盘结果还要计入 O(答案数·n²)。
>
> **易错点：** 对角线编号公式写错；撤销时漏删一个集合；棋盘行复用同一个可变数组；只判断相邻行；问计数时仍构造所有字符串造成额外开销。

## 10. 动态规划

### Q069：爬楼梯为什么是动态规划，怎么把空间降到 O(1)？

> **核心思路：** 到第 i 阶的最后一步只能从 i-1 或 i-2 来，所以 `dp[i]=dp[i-1]+dp[i-2]`。每次只依赖前两个状态，我会用两个变量滚动更新。
>
> **不变量/关键步骤：** 更新到第 i 阶前，两个变量分别代表 i-2 和 i-1 阶的方案数；先算新值，再整体向前移动。边界 n=0、1、2 要按题目对“空走法”的定义处理。
>
> **复杂度：** 时间 O(n)，空间 O(1)。矩阵快速幂可到 O(log n)，但普通面试先讲清状态和边界。
>
> **易错点：** 初始值与题意不一致；滚动变量覆盖顺序错误；方案数溢出 int；把“每次最多走 k 阶”的扩展仍写成只依赖两项。

### Q070：打家劫舍的状态为什么不能只看当前房子的金额？

> **核心思路：** 当前房子拿不拿取决于前一间是否拿过，所以我定义 `dp[i]` 为处理到 i 时能得到的最大金额，转移是“不拿当前的 dp[i-1]”和“拿当前的 dp[i-2]+nums[i]”取最大。
>
> **不变量/关键步骤：** 滚动到 i 前，prev1 是前 i-1 间的最优解，prev2 是前 i-2 间的最优解；当前最优只在两种互斥选择中取最大。
>
> **复杂度：** 时间 O(n)，空间 O(1)。环形房屋需要分别计算排除首家和排除末家的两个线性区间。
>
> **易错点：** 贪心选局部大值；长度为 0、1、2 的边界；环形版本同时选首尾；如果金额允许负数，要确认是否允许一间都不拿。

### Q071：零钱兑换最少硬币数怎么定义不可达状态？

> **核心思路：** 我定义 `dp[x]` 为凑出金额 x 的最少硬币数，初始 `dp[0]=0`，其他位置设成一个明确的无穷大；对每个金额尝试最后使用的硬币。
>
> **不变量/关键步骤：** 计算 dp[x] 时，所有更小且会被依赖的金额已经是最优；只有 `dp[x-coin]` 可达时才能转移，最终无穷大表示无法凑出。
>
> **复杂度：** 金额为 A、硬币种类 c，时间 O(A·c)，空间 O(A)。
>
> **易错点：** 无穷大加一溢出；把最少硬币和组合数量的循环含义混淆；硬币含 0 或负数；错误初始化为 0 导致所有金额看起来可达。

### Q072：最长递增子序列的 O(n²) 和 O(n log n) 解法分别在维护什么？

> **核心思路：** O(n²) 的 dp[i] 表示以 i 结尾的最长递增子序列长度；O(n log n) 的 tails[len] 表示长度为 len+1 的递增子序列能取得的最小结尾，用二分替换结尾。
>
> **不变量/关键步骤：** DP 只从值更小的前驱转移；tails 数组始终单调，并且同样长度保留更小结尾不会让未来选择变差。tails 的内容不一定就是原序列中的最终 LIS。
>
> **复杂度：** 基础 DP 时间 O(n²)、空间 O(n)；tails 解法时间 O(n log n)、空间 O(n)。恢复具体序列还需要 predecessor 等额外记录。
>
> **易错点：** 严格递增与非递减选择 lower bound/upper bound 不同；把 tails 直接当最终子序列输出；空数组；只返回全局 max 时忘记 dp[i] 是“以 i 结尾”。

### Q073：最长公共子序列为什么用二维 DP？

> **核心思路：** 两个字符串各有一个处理进度，我定义 `dp[i][j]` 为前 i 个字符和前 j 个字符的 LCS 长度。末尾相等就接在 `dp[i-1][j-1]` 后，不等就丢掉一边末尾取最大。
>
> **不变量/关键步骤：** dp 的行和列 0 表示空前缀；填到 `(i,j)` 时，它依赖的左、上、左上都已计算。字符索引用 i-1、j-1，DP 下标表示长度。
>
> **复杂度：** 时间 O(mn)，空间 O(mn)；只求长度可以滚动到 O(min(m,n))，恢复具体序列通常保留表或决策。
>
> **易错点：** 把子序列当子串要求连续；字符相等时仍错误取左上最大；下标偏一；滚动数组从左到右覆盖了上一行左上值。

### Q074：编辑距离的三个转移分别代表什么？

> **核心思路：** 我定义 `dp[i][j]` 为把字符串 A 的前 i 个字符变成 B 的前 j 个字符的最少操作。末尾不同就考虑删除 A 末尾、插入 B 末尾、替换末尾，取最小再加一。
>
> **不变量/关键步骤：** `dp[i-1][j]` 对应删除，`dp[i][j-1]` 对应插入，`dp[i-1][j-1]` 对应替换；末尾相同直接继承左上。首行首列分别是连续插入和删除。
>
> **复杂度：** 时间 O(mn)，空间 O(mn)，只求距离可滚动到 O(min(m,n))。
>
> **易错点：** 插入和删除方向讲反；漏掉首行首列初始化；字符相同仍加一；题目若有不同操作权重，不能继续统一加一。

### Q075：0/1 背包为什么一维数组必须倒序遍历容量？

> **核心思路：** 每件物品只能使用一次。压成一维后，我从大容量向小容量更新，这样 `dp[c-weight]` 仍然是上一轮、也就是还没使用当前物品的状态。
>
> **不变量/关键步骤：** 处理完前 i 件物品后，dp[c] 是容量 c 的最优价值；倒序保证同一件物品在这一轮不会被重复拿。完全背包允许重复使用，才会正序遍历容量。
>
> **复杂度：** 物品数 n、容量 W，时间 O(nW)，空间 O(W)。
>
> **易错点：** 0/1 背包容量正序导致变成完全背包；恰好装满和不超过容量的不可达初始化不同；价值或容量为 0；只求价值和恢复具体选项需要的信息不同。

### Q076：分割等和子集怎么转成 0/1 背包？

> **核心思路：** 我先求数组总和。如果总和是奇数就不可能平分；偶数时问题变成能否从每个数最多选一次，凑出 target=sum/2，也就是 0/1 背包可达性。
>
> **不变量/关键步骤：** `dp[c]` 表示处理过的元素能否凑出 c，初始只有 dp[0] 为 true；每个正数都从 target 向下更新，保证本轮不会重复使用同一个数。dp[target] 变为 true 后可以提前结束。
>
> **复杂度：** n 个数、目标和 S/2，时间 O(nS)，空间 O(S)，这里 S 表示目标容量而不是元素个数。
>
> **易错点：** 忘记先判断奇偶；容量正序导致一个数被重复使用；总和用 int 溢出；输入允许负数时普通背包下标不成立；把“存在一种分法”和“统计分法数量”混淆。

### Q077：最大子数组和为什么可以只保留一个状态？

> **核心思路：** 我定义 current 为必须以当前位置结尾的最大子数组和。到新元素时，要么从它重新开始，要么接在之前的 current 后面，取较大值；全局答案再记录所有结尾中的最大值。
>
> **不变量/关键步骤：** 扫描到 i 后，current 是以 i 结尾的最优解，best 是前缀 `[0,i]` 内任意连续子数组的最优解。两者含义不同，更新 current 后再更新 best。
>
> **复杂度：** 时间 O(n)，空间 O(1)。如果要返回区间，再维护当前起点和最佳左右边界，复杂度不变。
>
> **易错点：** 把 best 初始化为 0，导致全负数组错误返回空子数组；更新顺序不对；把子数组当子序列；要求返回区间时，相等情况下的 tie-break 没定义。

### Q078：不同路径带障碍怎么做滚动 DP？

> **核心思路：** 到一个可走格子的路径数等于上方加左方。我用一维 dp 按行扫描，dp[j] 在更新前代表上方，dp[j-1] 是本行左方；遇到障碍就把 dp[j] 清零。
>
> **不变量/关键步骤：** 扫描到当前格后，dp[j] 表示从起点走到当前行第 j 列的路径数；障碍位置必须为 0，不能把之前行留下的值继续传下去。起点可走时 dp[0] 初始化为 1。
>
> **复杂度：** m×n 网格时间 O(mn)，空间 O(n)，也可以选较短维度把空间写成 O(min(m,n))。
>
> **易错点：** 起点或终点是障碍；第一行第一列单独初始化时漏掉障碍后的全零传播；路径数溢出；题目允许斜走或带权时仍套普通加法。

### Q079：股票买卖题怎么用状态机统一理解？

> **核心思路：** 我会先定义每天结束后的状态，而不是背很多题解。最基本是 hold 表示持有一股的最大收益，cash 表示不持有的最大收益；交易次数、冷冻期和手续费只是给状态增加维度或修改转移。
>
> **不变量/关键步骤：** 每个状态都明确“当天结束时持有什么、用了几次交易、是否处于冷冻”；更新必须使用上一天状态，滚动变量时要保存旧值。一次交易、无限交易、最多 k 次分别限制买入所依赖的交易层。
>
> **复杂度：** 无限交易等常见版本时间 O(n)、空间 O(1)；最多 k 次通常时间 O(nk)、空间 O(k)。
>
> **易错点：** 同一天更新后的 cash 又被拿来买入，意外允许不符合题意的操作；手续费加在买卖两边重复扣；交易次数定义在买入还是卖出不一致；k 很大时未退化成无限交易优化。

## 11. 图与搜索

### Q080：岛屿数量为什么本质是连通分量计数？

> **核心思路：** 我扫描网格，每遇到一个尚未访问的陆地，就说明发现一个新的连通分量，答案加一，再用 DFS 或 BFS 把与它四方向连通的整座岛标记掉。
>
> **不变量/关键步骤：** 已扫描位置中的每块陆地要么已归入某座已计数岛屿，要么当前正被遍历；一次搜索结束后，该连通分量不会再次触发计数。可以用 visited，也可以按接口约定原地改网格。
>
> **复杂度：** 每个格子最多访问一次，时间 O(mn)，visited 空间 O(mn)；递归 DFS 最坏栈 O(mn)，原地标记不消除递归栈风险。
>
> **易错点：** 四连通和八连通混淆；字符 `'1'` 与数字 1；递归深度导致栈溢出；原地修改了调用方仍要使用的数据；空网格和不规则行长度。

### Q081：克隆图为什么一定要先放入映射再递归邻居？

> **核心思路：** 我用哈希表记录原节点到克隆节点的映射。第一次见到节点时先创建空壳克隆并放进映射，再递归克隆邻居，最后把克隆邻居接上。
>
> **不变量/关键步骤：** 映射中每个原节点只对应一个克隆对象；只要节点已进映射，后续遇到环或多条边指向它就直接复用。先登记再递归，才能打断环形依赖。
>
> **复杂度：** 时间 O(V+E)，映射和递归或队列空间 O(V)。
>
> **易错点：** 用节点值做 key，值重复时合并错误节点；先递归后登记导致环上无限递归；只复制节点没复制边；无向图的双向邻接被错误去重；输入 null。

### Q082：课程表能否完成怎么判断图里有没有环？

> **核心思路：** 课程是节点，先修关系是有向边。能完成所有课程等价于图是 DAG。我可以用 Kahn 算法不断取入度为 0 的课程，最后看处理数量是否等于节点总数，也可以用 DFS 三色标记找回边。
>
> **不变量/关键步骤：** Kahn 中队列只放当前没有未完成前置依赖的节点；弹出节点相当于完成它，并把后继入度减一。若最后还有节点没处理，它们位于环中或依赖环。
>
> **复杂度：** 建图和遍历时间 O(V+E)，邻接表、入度和队列空间 O(V+E)。
>
> **易错点：** 边方向建反；重复依赖导致入度重复计算；孤立课程没进队列；只判断队列是否曾为空而不是最终处理数；DFS 只用 visited，无法区分当前递归栈和已完成节点。

### Q083：怎么输出拓扑序，什么时候拓扑序不唯一？

> **核心思路：** 我用 Kahn 算法把每次入度为 0 的节点加入结果。结果长度等于 V 才有合法拓扑序；如果某一步同时有多个可选的零入度节点，通常说明顺序不唯一。
>
> **不变量/关键步骤：** 结果中的每个节点加入时，它的所有前驱都已经在结果里；每条边只在前驱出队时处理一次。若题目要求字典序最小，就把普通队列换成小顶堆。
>
> **复杂度：** 普通队列时间 O(V+E)、空间 O(V+E)；要求字典序时，堆操作使时间增加到 O((V+E) log V) 的量级。
>
> **易错点：** 有环时仍返回部分结果；“某一步多个零入度”判断唯一性要基于去重后的正确图；优先队列只保证一种最小序，不代表枚举所有序；边重复导致入度错误。

### Q084：无权图最短路为什么用 BFS？

> **核心思路：** 无权图每条边代价相同，BFS 按距离一层一层扩展，所以一个节点第一次被访问时，走到它的边数就是最短距离。
>
> **不变量/关键步骤：** 队列中节点的距离不会下降；入队时就标记 visited，防止同层多个父节点重复入队。需要恢复路径时记录 predecessor，找到目标后沿前驱回溯。
>
> **复杂度：** 邻接表表示下时间 O(V+E)，visited、距离、前驱和队列空间 O(V)。网格 BFS 对应 O(mn)。
>
> **易错点：** 出队才标记导致重复入队；图有权却仍用普通 BFS；多源问题逐个源点做 BFS；只记录距离没法恢复路径；不可达节点的返回值没约定。

### Q085：Dijkstra 的堆里为什么会有过期记录？

> **核心思路：** 我用 dist 保存当前最短距离，小顶堆保存候选 `(distance,node)`。某节点找到更短路径时直接再入堆，不做昂贵的 decrease-key；旧的较大候选以后出堆时会被识别为过期并跳过。
>
> **不变量/关键步骤：** 每次从堆中取出的、且距离等于 dist[node] 的记录，才是当前有效候选；用它松弛出边。边权必须非负，才能保证已确定的最短距离不会被未来路径推翻。
>
> **复杂度：** 邻接表加二叉堆通常是 O((V+E) log V)，空间 O(V+E)；允许重复堆项时堆空间可到 O(E)。
>
> **易错点：** 有负权边仍使用 Dijkstra；不跳过过期记录导致大量重复工作；距离相加溢出；无向边只加一个方向；把 BFS 的 visited 过早锁死节点。

### Q086：多源 BFS 什么时候比从每个源点各跑一次更好？

> **核心思路：** 当我要算每个位置到最近源点的距离时，我会把所有源点同时以距离 0 入队，再做一次 BFS。它相当于虚拟超级源点向所有真实源点连一条 0 成本边。
>
> **不变量/关键步骤：** 队列按距离层扩展，一个位置第一次被访问时，就是它到所有源点集合的最短距离；所有源点必须在搜索开始前一起入队并标记。
>
> **复杂度：** 图上 O(V+E)，网格上 O(mn)，空间 O(V) 或 O(mn)；比对每个源点单独 BFS 的乘法级成本低。
>
> **易错点：** 边扫描边发现源点并立即 BFS，破坏同时出发；源点重复入队；边有不同权重；要求到最近和要求到所有源点距离之和不是同一个问题。

### Q087：怎么判断一个图是不是二分图？

> **核心思路：** 我用两种颜色给每个连通分量染色。一个节点确定颜色后，所有邻居必须是相反颜色；若遇到已染色邻居颜色相同，就存在奇环，不是二分图。
>
> **不变量/关键步骤：** 已处理边的两个端点颜色始终相反；图可能不连通，所以外层要从每个未染色节点启动 BFS 或 DFS。颜色数组同时承担 visited 的作用。
>
> **复杂度：** 时间 O(V+E)，颜色和队列或递归栈空间 O(V)。
>
> **易错点：** 只从节点 0 搜导致漏掉其他分量；自环应立即失败；无向图邻接边重复出现不是错误；把节点编号奇偶当颜色；递归深度过大。

## 12. 并查集

### Q088：并查集的路径压缩和按秩合并分别解决什么？

> **核心思路：** 并查集维护若干互不相交集合。find 找代表元并做路径压缩，让访问过的节点直接靠近根；union 按 size 或 rank 把较小树挂到较大树下，避免树变高。
>
> **不变量/关键步骤：** 同一集合中的节点最终有同一个根；只有根的 parent 指向自己；合并前先找两个根，根相同就不重复合并。size/rank 只在根节点上有意义。
>
> **复杂度：** 两种优化一起使用时，m 次操作总时间 O(m·α(n))，几乎可看作常数；空间 O(n)。
>
> **易错点：** 直接把普通节点 parent 相连而不是根；路径压缩后错误更新 rank；递归 find 在极端未优化树上栈过深；删除或拆分集合不是普通并查集擅长的操作。

### Q089：冗余连接为什么可以边读边 union？

> **核心思路：** 一开始每个节点独立。按输入顺序处理一条无向边 `(u,v)` 时，如果两端已经属于同一集合，再加这条边就会形成环，它就是当前冗余边；否则把两个集合合并。
>
> **不变量/关键步骤：** 处理完前缀边后，并查集准确表示这个前缀图的连通分量；只有连接同一分量内部两个点的边会首次闭合一个环。若题目要求返回最后一条候选，就按输入顺序保存最新命中。
>
> **复杂度：** E 条边时间 O(E·α(V))，空间 O(V)。
>
> **易错点：** 有向冗余连接不能直接套这个结论；节点编号不连续却按边数开数组；题目要求最后一条而提前返回；自环和重复边的语义没按题意处理。

### Q090：账户合并怎么用并查集完成？

> **核心思路：** 我把邮箱当作账户之间的连接证据。扫描每个账户时，把同一账户内的邮箱 union，并记录邮箱对应的用户名；最后按根节点把邮箱分组、排序后输出。
>
> **不变量/关键步骤：** 只要两个邮箱通过一个或多个账户间接相连，它们就有同一个根；分组阶段必须对每个邮箱重新 find，拿路径压缩后的最终根。用户名冲突要按业务规则处理，不能默认覆盖就是正确。
>
> **复杂度：** 邮箱出现总数为 M，并查集操作近似 O(M·α(M))，分组内排序总计最坏 O(M log M)，空间 O(M)。
>
> **易错点：** 用用户名 union 导致同名不同人被合并；邮箱重复时没去重；只 union 相邻账户而不是账户内邮箱；HashMap 输出顺序不稳定；冲突用户名被静默覆盖。

## 13. 设计题与并发

### Q091：现场手写 LRU Cache，你会怎么保证 get 和 put 都是 O(1)？

> **核心思路：** 我会用 HashMap 做 key 到节点的 O(1) 定位，再用双向链表维护新旧顺序。访问或更新节点就把它移到头部，容量满时删除尾部最久未使用节点，并同步删除 Map。
>
> **不变量/关键步骤：** Map 中每个 key 恰好对应链表中的一个真实节点；链表从头到尾按最近使用到最久未使用排列；我会用头尾哨兵统一插入删除，任何结构修改都同时维护 Map、prev 和 next。
>
> **复杂度：** get、put、移动和淘汰都是均摊 O(1)，空间 O(capacity)。并发版本加锁后算法复杂度不变，但会有锁竞争。
>
> **易错点：** 更新已有 key 后又新增重复节点；淘汰链表却没删 Map；容量为 0；哨兵被误删；Java HashMap 不是线程安全，简单加 ConcurrentHashMap 也不能让 Map 与链表的组合操作原子化。

### Q092：生产者消费者现场题，你会优先怎么写？

> **核心思路：** Java 现场如果允许标准库，我优先用有界 `BlockingQueue`：生产者 put，消费者 take，让队列负责等待和唤醒。有界容量还能提供背压，避免生产速度长期高于消费速度把内存撑爆。
>
> **不变量/关键步骤：** 队列元素数始终在 0 到 capacity 之间；put 成功才算生产完成，take 成功后元素只交给一个消费者。要定义关闭协议，例如 poison pill、关闭标记加中断，不能只靠线程自然结束。
>
> **复杂度：** 常见数组阻塞队列入队出队 O(1)，空间 O(capacity)；实际吞吐受锁竞争、任务耗时和上下游速度限制。
>
> **易错点：** 手写 `wait/notify` 时用 if 而不是 while 防虚假唤醒；在错误对象上等待；持锁执行耗时业务；无界队列没有背压；吞掉 InterruptedException；多个消费者时 poison pill 数量不足。

## 14. AI 与 Java 后端现场编码

### Q093：怎么写一个支持退避、抖动和总截止时间的异步重试器？

> **核心思路：** 我会让调用方传入异步操作、可重试异常判定、最大次数和总 Deadline。每次失败后根据指数退避算等待时间，再加随机 jitter，但等待和下一次调用都不能超过剩余 Deadline。
>
> **不变量/关键步骤：** 任意时刻都只有一个逻辑重试链；每次开始前重新计算剩余时间；只重试瞬时故障，参数错误和业务拒绝直接失败；成功、不可重试、次数耗尽、Deadline 到达四种路径都只完成 Future 一次。
>
> **复杂度：** CPU 工作 O(r)，空间 O(r) 或用调度器状态机做到 O(1)，r 为尝试次数；墙钟时间由调用耗时与退避决定，不能只报算法时间。
>
> **易错点：** 用 `Thread.sleep` 阻塞业务线程；每一层各给完整超时导致总耗时失控；没有 jitter 引发重试风暴；取消没有向下游传播；对非幂等写请求自动重试造成重复副作用。

### Q094：Token Bucket 限流器要维护哪些状态？

> **核心思路：** 我会维护桶容量、当前 Token 数、补充速率和上次补充时间。请求到来时先按经过时间补 Token，再判断是否够扣；够就原子扣减，不够就拒绝或返回需要等待多久。
>
> **不变量/关键步骤：** Token 始终在 0 到 capacity 之间；补充量基于单调时钟；“补充、判断、扣减”必须是一个原子操作。分布式实现可以用 Redis Lua 或带版本的 CAS，不能先读再分两次写。
>
> **复杂度：** 单机每次请求 O(1) 时间、O(1) 状态；按用户或租户限流时空间 O(活跃 key 数)，需要 TTL 清理冷 key。
>
> **易错点：** 用墙上时间遇到时钟回拨；浮点累计误差；并发超扣；只限平均速率却没理解 capacity 允许突发；Redis 故障时没有明确 fail-open 还是 fail-closed 策略。

### Q095：怎么现场实现多个检索列表的 RRF 融合？

> **核心思路：** 我会按稳定文档 ID 去重，对每个召回列表中的文档累加 `1/(k+rank)`，不直接比较不同检索器不可比的原始分数。累加后按融合分数排序，取最终 Top K。
>
> **不变量/关键步骤：** 同一文档无论出现在哪个列表都汇总到同一个 ID；rank 从 1 还是 0 开始要统一；每个列表可配置权重，但权重、常数 k 和截断深度必须版本化，结果并列时用稳定 ID 做确定性排序。
>
> **复杂度：** 所有候选条目总数为 N，累加 O(N)，全排序 O(M log M)，M 为去重后文档数；只取 Top K 可用堆降为 O(M log K)，空间 O(M)。
>
> **易错点：** 用文本内容而不是稳定 ID 去重；把向量距离和 BM25 分数直接相加；rank 起点不一致；同一检索器重复文档被多次加分；融合后忘记权限过滤或把过滤放得太晚造成泄露。

### Q096：怎么实现受 Token 预算约束的父子分块？

> **核心思路：** 我会先按标题、段落和句子边界形成语义父块，再用目标模型的真实 tokenizer 把过大的父块切成可检索子块。子块保存 parentId、原文偏移和顺序，召回子块后可以按预算回取父块或相邻上下文。
>
> **不变量/关键步骤：** 每个子块 Token 数不超过硬上限；文本覆盖连续且可追溯回原文；优先在自然边界切，只有单句仍超限才做硬切；overlap 按 Token 计算并设上限，不能让一个超长词或代码行造成死循环。
>
> **复杂度：** tokenizer 近似线性扫描，时间 O(n)，生成块和索引元数据空间 O(n)；如果每次从头重新计数可能退化到 O(n²)。
>
> **易错点：** 用字符数冒充 Token 数；父块本身无限大，召回时再次爆上下文；重叠重复导致检索偏置；切断代码块、表格或 Markdown 结构；模型或 tokenizer 升级后旧索引预算失真。

### Q097：流式 JSON 或 Tool Call 参数解析器怎么避免每个分片都从头解析？

> **核心思路：** 我会使用增量 UTF-8 解码器，并维护解析状态：当前是否在字符串内、是否转义、括号深度、已完成字段和未完成缓冲。每个 chunk 只消费一次，检测到一个完整 JSON 值后再交给正式 JSON Parser 校验。
>
> **不变量/关键步骤：** 已消费前缀要么属于已完成值，要么完整保存在有限的未完成状态中；字符串里的 `{`、`}` 不改变深度；反斜杠和跨 chunk 的多字节字符必须延续状态。并行 Tool Call 要按 callId 或 index 分别维护缓冲。
>
> **复杂度：** 总输入 n 字节时解析 O(n)，缓冲空间 O(当前未完成值大小)；每次把全部历史重新 parse 会退化到 O(n²)。
>
> **易错点：** 直接按字节转字符串切坏 UTF-8；没处理转义引号；用括号计数器却忽略字符串内容；无限增长输入没有大小和深度限制；业务在 JSON 尚未完整校验前就执行有副作用工具。

### Q098：现场写 SQL 统计每周 P95 延迟并找异常周，怎么拆？

> **核心思路：** 我会先把原始请求按周和必要维度分组，用数据库支持的 percentile 函数算 P95、请求数和错误率；再用 CTE 或子查询，对周指标使用 `LAG` 或滚动基线比较，最后按明确阈值标异常。
>
> **不变量/关键步骤：** 时间统一到同一时区后再 `date_trunc`；P95 基于原始请求延迟而不是先算日均再取分位数；低样本周要单独过滤或标记；异常规则、窗口和排除发布期等条件必须显式写出。
>
> **复杂度：** 扫描 N 条记录至少 O(N)，精确分位数常涉及分组排序，最坏可到 O(N log N)；合适的时间分区、覆盖索引和近似分位聚合能降低实际成本。
>
> **易错点：** MySQL、PostgreSQL、ClickHouse 的分位函数语法不同；整数除法；NULL 和超时样本被静默丢掉；时区导致周边界错位；把 P95 上升直接解释成业务根因而没有样本量和维度下钻。

### Q099：怎么用 CAS 设计一个不会被两个 Worker 同时领取的任务租约？

> **核心思路：** 任务表保存 status、owner、leaseUntil 和 version。Worker 领取时执行一条条件 UPDATE：只有任务待处理，或旧租约已过期，并且 version 符合预期时，才能写入新 owner、租约时间并递增 version；受影响行数为 1 才算领取成功。
>
> **不变量/关键步骤：** 同一时刻只有持有当前 owner 和 version 的 Worker 能续租或完成任务；长任务在租约过半前 heartbeat；完成更新也要带 owner、version 条件，防止旧 Worker 在租约过期后覆盖新 Worker 的结果。
>
> **复杂度：** 命中主键或合适待执行索引时，单次 CAS 通常 O(log N) 的索引访问和 O(1) 行更新；轮询扫描成本取决于索引、批量大小和竞争。
>
> **易错点：** 先 SELECT 再无条件 UPDATE；租约到期后旧 Worker 仍提交成功；使用不同机器本地时间判断过期；heartbeat 和业务执行不协调；任务副作用没有业务幂等键，租约只能避免并发领取，不能保证 Exactly-once。

### Q100：怎么设计一个幂等的异步任务创建接口？

> **核心思路：** 我要求调用方提供 Idempotency-Key，并把 tenantId、key 和请求体规范化哈希一起落库，建立唯一约束。首次请求在事务中创建任务并返回 taskId；重复请求哈希相同就返回同一任务，哈希不同就报冲突。
>
> **不变量/关键步骤：** 同一租户和幂等键最多对应一个业务意图、一个任务 ID；唯一约束是并发竞争的最终裁决，不依赖“先查没有再插入”；任务记录提交成功后再可靠投递，可用 Outbox，避免数据库成功但消息丢失。
>
> **复杂度：** 哈希请求体 O(payload size)，唯一索引查询或插入通常 O(log N)，接口额外状态空间 O(任务数)；幂等记录要有与业务重试窗口匹配的保留期。
>
> **易错点：** 幂等键不带租户导致串数据；相同 key 不校验请求体；只在 Redis 短暂缓存响应却数据库重复创建；事务提交前就发消息；失败响应是否可重放没有定义；把 HTTP 重试幂等误说成下游每个副作用天然幂等。
