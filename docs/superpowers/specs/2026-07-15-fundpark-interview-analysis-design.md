# 丰泊国际面试分析文档设计

## 目标

基于仅包含面试官提问的逐字稿，结合工作区内的简历、项目资料、既有面试分析和丰泊国际公司报告，生成一份可复习、可直接用于下一轮面试的 Markdown 文档。

最终文件为 `面试分析/丰泊国际-面试整理与答案.md`，版式与该目录中的现有“面试整理与答案”文档保持一致。

## 事实边界

- 逐字稿缺少候选人的现场回答，不把推断写成事实。
- 年龄、薪资、住址、离职进度、到岗时间等个人事实统一使用 `[按实际情况填写]`。
- 技术题和项目题给出基于现有材料的推荐答案，并在必要处提示应按真实实现调整。
- 面试表现只根据面试官的重复追问、纠正、打断、转题和明确评价判断，使用“推断”“风险信号”等措辞。
- 公司信息以工作区现有的 `公司/丰泊国际FundPark_公司深度分析报告.md` 为依据，不新增未经核验的事实。

## 文档结构

1. 开篇说明：材料边界、面试主线和总体判断。
2. 面试基本信息：公司、岗位方向、形式、面试官风格、问题覆盖面。
3. 过程分析：按开场核验、动机匹配、基础技术、工程能力、AI 项目、反向提问六个阶段复盘。
4. 问题与答案：按面试发生顺序分组，合并无信息增量的重复确认，保留连续追问的逻辑。
5. 公司与岗位信号：整理面试官透露的需求增长、文档缺失、AI 工具额度、Kubernetes 使用和创业团队特征。
6. 综合复盘：得分点、主要失分风险、岗位匹配度、通过概率只做定性判断。
7. 下一轮准备：按优先级列出必须背熟的答案、需要补做的技术验证和建议反问。

## 单题模板

关键问题使用以下结构：

- 问题标题：清洗口语和识别错误，但不改变原意。
- 面试官意图：说明考察的知识、真实性或岗位匹配点。
- 现场风险信号：根据追问方式说明可能未答准、答虚或缺少例子的位置。
- 参考答案：第一人称、口语化、可直接复述；先给结论，再讲原理、实践与边界。
- 可能追问：仅在高风险题中补充一到三个最可能的追问及应答要点。

简单事实确认题不强行套用完整模板，避免文档冗长。

## 内容重点

- 背景与动机：离职原因不能只归结为“公司不能用先进 AI 工具”，要补足成长空间、业务价值与长期方向，同时避免贬低原团队。
- 公司理解：把丰泊国际准确表述为跨境电商金融科技和持牌放贷业务，而不是泛 AI 公司。
- Java 基础：补齐依赖注入、ThreadLocal、MyBatis-Plus、ConcurrentHashMap、ReentrantLock/AQS、事务传播、幂等、分布式事务和 JVM GC。
- React：修正箭头函数 `this`、函数组件 hooks 和类组件生命周期映射。
- AI 周报：明确自动采集与 LLM 的边界，使用“确定性统计负责数字，LLM 负责表达和交互”。
- CodeWiki：用具体研发场景说明 Wiki、GraphRAG 和知识图谱的价值，不把“生成文档”当作全部价值。
- 记忆系统：讲清分层记忆如何减少热上下文占用、跨会话画像如何保持一致，以及原始证据如何下钻。
- Hermes/Harness：纠正语音识别，区分 Hermes Agent、agent harness 和记忆插件的职责。

## 验收标准

- 文件位于指定目录，标题和层级风格与既有样例一致。
- 覆盖逐字稿中的所有实质性问题，没有遗漏整类技术主题或项目追问。
- 不杜撰候选人个人事实、现场原话、项目数据或面试结果。
- 技术答案准确，示例代码可读且 API 用法正确。
- 对面试过程有证据支持的分析，不只是题库汇总。
- Markdown 表格、引用、代码块和标题层级通过结构检查。
- 全文没有待办标记、内部说明或未解释的占位符；仅保留约定的 `[按实际情况填写]` 个人事实占位。
