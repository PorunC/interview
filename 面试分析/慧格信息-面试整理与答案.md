## 三、记忆系统浅问（本场唯一技术深问）

### Q4. ⚠️ 25 年为什么想做记忆压缩系统？当时 Claude Code 已经有内置压缩功能了吧？

> 这是本场唯一的技术深问。面试官的点：既然 Claude Code 已有压缩，你为什么还要做？要讲清差异 + 你的场景需求。

**参考答案**（差异 + 场景）：
> 对，Claude Code 当时确实有内置压缩（compact），但它的压缩和我做的不是同一层问题，我讲下区别：
>
> **宿主自带 compact**：解决的是当前会话接近窗口上限后如何继续对话。我不会断言它内部一定是“黑盒暴力摘要”或一定不能恢复证据，因为不同版本实现可能变化；我只比较自己能证明的能力。
>
> **我做的系统解决的是不同问题**：
> 1. **跨会话失忆**：compact 只管当前会话，会话结束即失忆。我的 L0~L3 让记忆跨会话沉淀。
> 2. **证据可追溯**：通用摘要可能省略错误日志、路径和参数等精确细节；Context Offload 把完整 Tool Result 放到 refs，Prompt 只留摘要和 `result_ref`，需要时沿引用找回--"热路径有损、冷路径可还原"。
> 3. **记忆组织与更新**：L1 入库前先召回相似候选，再由 LLM 判断 `store/skip/update/merge`，并保留 `source_message_ids` 和 L0 证据。当前没有独立事实置信度、候选区、自动晋升或时间衰减，这些是明确的下一版治理项。
>
> 一句话：**宿主 compact 主要管当前会话续跑，我这层同时管跨会话记忆和高体积 Tool Result 的可追溯卸载。** 两者可以共存，不需要贬低宿主能力来证明项目价值。

### Q5. 这个系统现在可以接到任何工具里面，是吗？

**参考答案**：
> 设计目标是**宿主无关**：核心记忆能力（TdaiCore）和宿主适配分离，已接入的宿主通过 Hook 或 HTTP Gateway 调同一套核心。换 Runtime 时核心存储和召回逻辑可以复用，但仍要为新宿主实现生命周期、身份和消息格式适配，不能理解成任何工具零改动即插即用。

### Q6. 这个是你独立负责的，工作模式是什么？产品交互？

**参考答案**（统一框架，避免"独立"被误解）：
> “独立负责”不能先定义成技术 end-to-end，我会先按真实 RACI 澄清：
> - 项目真实团队规模、正式角色和需求来源是 **[待本人按记录填写]**。
> - 我亲自负责的设计和模块是 **[填写代码、评审或工单可证明的范围]**；同事协作模块是 **[填写]**，不能预设“调度器、压缩层、冲突检测都由我写”。

### Q7. L0 到 L3 多层记忆架构每一层大概是什么？

**参考答案**（基于真实实现，简短版）：
> 四层从原始到抽象：
> - **L0 原始对话证据**：保存原始用户和助手消息，兜底审计和原话检索；工具结果卸载属于另一条短期链路。
> - **L1 原子记忆**：从增量消息抽取 `persona / episodic / instruction` 三类记录，可检索、去重和更新，不是会话摘要。
> - **L2 场景归纳**：把 L1 点状事实按主题/场景聚合，给宏观上下文。
> - **L3 长期画像**：生成紧凑的 Persona，沉淀相对稳定的背景、偏好和协作方式。
>
> 加载时，L3 Persona 正文和完整 Scene Navigation 放稳定 system 区，本轮相关的少量 L1 放 user 前缀；L2 场景正文沿导航按需读取，需要原话时再搜 L0。不是完整 L2/L3 每轮常驻。

| 薪资 | 20% 涨幅被接受 | ★★★★ |

| 环节 | 风险 | 严重度 |
|------|------|--------|

### 下来必做（为 founder 二面准备）

1. **补美股 + 量化/金融 AI 基础认知**：
   - 了解美股市场基础（交易机制、主要指数、ETF）。
   - 了解 AI 在金融的典型落地：量化选股、研报摘要、舆情分析、风控、智能投顾。
   - founder 是基金背景，二面可能问"你觉得 AI 在美股投资能怎么用"--要有思路。

2. **准备"我的能力怎么落地到你们场景"**：
   - 记忆系统 -> 金融场景：agent 记住用户投资偏好、历史决策、风险承受度，跨会话个性化。
   - RAG/GraphRAG -> 金融场景：研报/公告/新闻的检索 + 知识图谱（公司-行业-产业链关系）。
   - 这是二面最可能问的"你能给公司带来什么"。

3. **准备和 founder 沟通的方式**：
   - 产品方明确提示"founder 说话含糊，不要猜着做，要多确认"。二面如果 founder 给模糊方向，要**当场复述确认**："我理解您说的是 X 方向，对吗？"而不是自己猜完去做。
   - 主动给自己的思考，不只是等指令。

4. **网络问题**：下次面试前测网络，卡顿会严重影响体验（这场已多次被提）。

## 八、总结

这场慧格初筛基本是**通过型**--技术没深挖、动机匹配、薪资接受、已推进 founder 二面。面试官明确说"听得挺详细、挺仔细"，产品方也聊得顺畅。

**核心信号**：
1. 公司全 vibe coding + 无额度最新模型，对 AI 工具投入力度大--这是给你的加分项，进去能深度用 AI。
2. 看重自驱力 + 学习能力，分工不清晰要自己找方向，和 founder 直接沟通。
3. founder 二面是真正的考验--懂金融+AI，要准备业务理解 + 能力落地的话术。

**下来优先级**：
1. 补美股 + 金融 AI 基础认知（为 founder 二面）。
2. 准备"记忆系统/RAG 怎么落地到美股金融场景"的话术。
3. 练和 founder 沟通的方式（复述确认 + 主动给思考）。
4. 网络问题下次提前测。

**一句话**：这轮过了，但别松懈--founder 二面才是硬仗，他既懂金融又懂 AI，纯技术话术不够，要能讲"我的能力怎么解决你们的金融场景问题"。
