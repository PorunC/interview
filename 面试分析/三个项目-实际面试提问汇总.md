# 三个项目：实际面试提问汇总

> 整理范围：`面试分析/` 下已有面试复盘。
>
> 口径：保留文档中明确记录为面试官提问、连续追问、挑战或面试官原话的问题；合并同义重复问题。排除“可能追问”“备选题”“下一轮建议题”。题目后的括号为来源面试。
>
> 说明：美狮物流、丰泊国际两份材料明确说明只保留了面试官声道，因此问题可以确认是现场问法，但候选人当时的完整回答无法从材料确认。

## 一、最高频主线

这三类项目被反复验证的不是单个技术名词，而是以下问题：

1. **项目到底解决谁的什么问题，LLM 具体负责哪一层？**
2. **为什么不用固定规则、grep、Claude/Codex/Cursor 或现成压缩能力？**
3. **系统当前真实部署形态、数据流、使用情况和本人责任边界是什么？**
4. **数据或代码发生变化后，如何保证准确性、新鲜度、可追溯和可恢复？**
5. **当前已经实现了什么，哪些只是下一版设计？**

## 二、项目一：AI 周报系统

### 2.1 项目对象与业务价值

- 项目是定时采集、生成和推送的自动化流程吗？（安克 Q11）
- 大模型介入之后，推送的周报模板发生变化了吗？（安克 Q10）

### 2.3 “没有 LLM 也能做吗”与 LLM 边界

- 这个东西不用 LLM 也可以吗？听起来就是一个 workflow。（卓誉 Q5）

### 2.5 从“描述数据”到“根因分析”

- 老板看到销量下滑，追问“为什么销量下滑”，系统现在能做根因分析吗？（安克 Q14）

- 多系统日志已经集中后，出现一个异常告警时，如何定位真正根因？需要哪些数据、怎么处理、用什么方法快速排查？（小天才 Q5，基于周报项目的延展设计题）

## 七、复习优先级

### 第一优先级：多家公司重复追问

- 周报到底服务谁、原流程是什么、LLM 只做什么。
- CodeWiki 为什么不直接用 Claude/Codex/grep，今天的净收益是什么。
- Memory 是否扩大上下文窗口，长期记忆和短期 Offload 分别解决什么。
- Memory 的实际部署形态、插件生命周期和一轮请求数据流。
- L0-L3 每层定义、什么时候写入、什么时候召回。
- 事实冲突、抽取幻觉、置信度和来源证据怎么处理。
- CodeWiki 当前代码变化后，旧图和旧向量如何失效；哪些一致性问题尚未解决。

### 第二优先级：架构深挖

- CodeWiki 的 AST、Chunk、节点/边、GraphRAG 扩图和上下文装包。
- 向量库选型、索引、更新删除、Embedding 模型升级。
- Memory 的调度器、Hybrid Recall、Context Offload、引用恢复和后台异步处理。

### 第三优先级：生产与协作

- 用户量、QPS、部署环境、CICD、API 池、监控和失败降级。
- “独立负责”的 RACI 边界，项目时间线、团队规模和真实使用情况。
- AI Coding 的实际工作流、Review、测试和上线责任。
